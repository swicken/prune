Wall time includes service/tool latency and overlapping execution of arms. Token counts are the CLI-reported output usage, not cost. Code lines include generated checks and are not a quality score. Two runs are insufficient to infer a stable performance advantage.

Both arms passed reuse, negative-transfer rejection before mutation for both callers, shared-tax behavior, independent-policy source preservation, iterator/log/error preservation, cleanup of the newly unused helper, endpoint regression checks, complete duration parsing, iterator root-cause repair, requested explanation coverage, and debt classification. Source review confirmed canonical tax helpers in all four submissions, separate independently owned policies, all three requested date-input tradeoffs, and only the two real compromises in the debt ledger.

**Known failure:** all four submissions failed arbitrary-key grouping. Three used a plain object with inherited entries and threw on `__proto__`. Prune's second run added an own-property guard but assigned `__proto__` through the legacy setter, so that category was not an own enumerable entry. A null-prototype dictionary or explicit own data-property definition would satisfy the contract. Normal-key checks run by the agents did not expose this; their completion reports were therefore broader than the hidden evidence. This remains a limitation of the evaluated skill/model combination, not an adapter defect.

## Grader review and limits

During review, the reuse grader initially rejected valid imported aliases. It now reloads the feature after replacing the canonical helper and accepts both module imports and imported aliases; a copied implementation still fails. The grouping grader was strengthened to require an own entry, exposing the second Prune submission's prototype-setter bug. The regression grader clears bytecode caches before green/red runs. All four saved submissions were rescored with the same final graders. These corrections improved the graders, not the submissions.

Grader self-tests pass 12 good references, reject 12 empty submissions and an under-delivering duration stub, accept both import forms, and reject duplicated slug code. Passing contracts do not prove all edge cases, safety, or maintainability. Report-depth length and taxonomy fields are rough automated checks; semantic claims above also rely on source review.

Environment: Codex CLI 0.136.0, Python 3.14.7, Node 24.15.0 on macOS. For the Node 18 case, `Object.groupBy` was disabled; this is a capability simulation rather than execution under an actual Node 18 binary. The CLI default model was not pinned and was not identified in captured turn metadata. A model-catalog decoding warning occurred, and CLI-managed bundled tools were still available despite isolated user config. Both arms used the same runner/environment, but these limitations prevent model-specific or broadly reproducible performance claims. Future trials should pin the model and run the compatibility case on Node 18.

The live pilots loaded the core skill; they did not independently activate the dedicated debt/review/audit skills or test installed-host end-to-end UX. Debt requests named `prune:` markers in both arms. They demonstrate behavior under explicit requests, not autonomous skill discovery.
